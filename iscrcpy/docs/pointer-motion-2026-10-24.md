# 指针移动修正与测量（2026-10-24）

## 真机观察

设备为用户提供的 iPhone 12 Pro，实际屏幕 1170×2532；此次 AirPlay 解码帧为
500×1080。两者不能混称。归一化坐标以当前手机画面为参照。

在旧移动策略下，先归位，再发送相同总位移 `(60, 60)`，全程不按鼠标按钮：

| 方式                                              | 画面中光标中心，约值 |
| ------------------------------------------------- | -------------------- |
| 一次发送，由旧代码分成约 20 counts / 16 ms 的报告 | (285, 283)           |
| 六次各发送 (10, 10)，每次调用完成再间隔 100 ms    | (261, 261)           |

落点相差约 (24, 22) 个镜像像素，说明报文大小、发送节奏或其相关主机处理会影响落点。
两组经 MCP 的调用开销不同，这不是单独测量 iOS 加速曲线的实验，也不能排除传输时序影响。
这里只报告人工观察的近似中心，不作为精确基准或成功率统计。

旧校准约为横向 105.82、纵向 233.24 HID counts 覆盖归一化单位长度。
其名义步长约为 4.7×4.6 个镜像像素，或 11.1×10.9 个实际屏幕像素；
整数取整误差上限为半个名义步长，实际误差还会叠加加速和漂移。

## 修正

- 统一报告策略：单轴 ±1 count，每次至少间隔 16 ms，斜向路径交错发送两轴步进。
  校准、定位、局部修正和拖动使用同一策略；归位仍用大报告撞边并等待稳定。
- 校准记录加入策略标识，旧速度下的校准不再加载，必须重新测量。
- 拖动时长作为下限，不再用改变报告大小/频率满足指定时长；超过操作预算的路径明确失败。
- 局部反馈锚定实际观察位置，始终向原始目标修正，不将偶发落点误差写入全局偏移。
- 状态返回名义归一化步长及镜像像素步长，明确这不是实际屏幕分辨率或精度保证。

## 验证

单元测试覆盖速度相关增益的模拟主机、横纵/斜向/正反向报告、不同拖动时长、旧校准失效、
连续反馈的目标保持、延迟主机、人工接管和取消。集成测试覆盖真实桌面 MCP 链路。
已通过 27 项 MCP 单元/协议测试、Electron MCP 集成测试、类型检查、相关代码 ESLint
及生产构建。模拟测试不能用于推导真机误差。
